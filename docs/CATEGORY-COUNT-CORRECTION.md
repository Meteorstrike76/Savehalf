# Matching category counts and Woolworths cycle

Category badges now combine collected-product counts with eligible uploaded advertisements. Source, store, search, price, half-price mode, product type, photo/freshness, followed/excluded title words and hidden IDs all affect totals. The selected department does not zero sibling totals: each badge describes how many matching listings that department contains. Regional advertisements remain separate listings, not automatically deduplicated SKUs. Independent provider sections keep their separate totals.

Without device/title refinements, reuse the existing aggregate RPC and add catalogue totals locally. With those refinements, read the full matching sibling set using existing RLS-protected APIs: pages of 48, at most 960 rows/20 requests, one 12-second deadline, shared two-minute cache. The same set supplies refined product cards so matches beyond the original first page are visible. Normal reads use the feed's direct query semantics; search/minimum/unit-order reads use its existing range RPC. No database migration or permissions change is required.

Counts automatically refresh when their two-minute cache expires while the tab is visible, and on focus/visibility changes. Expired catalogue advertisements are recalculated on the existing 30-second clock. Failed, incomplete, duplicate or oversized match snapshots show unknown counts (a dash), rather than a fabricated zero or a partial exact total. Narrower filters allow a bounded exact count. Saved-view counts use the complete saved set.

Original review timestamps are unchanged; no dates have been rolled forward into a new week. The upload has 147 eligible offers on 21 Nov 2026.

Validation covers both-source totals, source-only and retailer-only totals, weekly-cycle expiry, complete sibling totals after category changes, cross-page title matches, aggregation cache expiry/error recovery and safe unknowns.
